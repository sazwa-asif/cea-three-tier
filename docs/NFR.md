# Non-functional requirements: how the design meets them, and where it does not

| NFR | How it is met | Honest gap |
|---|---|---|
| Scalability | Both tiers are in Auto Scaling groups (2 to 3 instances) behind load balancers, and tiers scale independently. | Maximum is 3 per tier to protect credits. The database is a single instance and scales only vertically (bigger class), not horizontally. |
| Availability / reliability | Two Availability Zones for every tier. ALB health checks on `/health` remove bad instances; the ASG replaces them. | RDS is single-AZ (Multi-AZ doubles database cost), so a database failure or AZ outage means downtime until recovery. NAT gateway is in one AZ only. |
| Elasticity | Target-tracking policy keeps average CPU near 50%: instances are added under load and removed afterwards. | Scaling reacts in minutes, not seconds. Not load-tested at large scale. |
| Security | Three network layers; security group per tier allowing only the previous tier; DB and app instances have no public address; DB encrypted at rest; secrets in Secrets Manager; IMDSv2 required; OIDC instead of stored keys; narrow IAM policies (one secret, two log groups, two ECR repos, SSM on tagged instances only); ECR scan on push. | Traffic is HTTP, not HTTPS (no domain/certificate). In production add an ACM certificate and HTTPS listener, WAF, and TLS to the database. Web instances have public IPs (needed without a NAT per web subnet). |
| Maintainability / deployability | One template, one pipeline, one deploy script. Every deploy is tagged with the git commit. Same Dockerfiles run locally and in the cloud. | The deploy uses `:latest`; rollback means re-running the pipeline on an older commit. No blue/green. |
| Performance / latency | Nginx serves static content directly; load balancing spreads requests; app and database are in the same region and close subnets; gunicorn with several workers. | No caching layer (CDN or Redis). No measured latency figures beyond the CloudWatch response-time graph. |
| Cost efficiency | Small instance types, gp3 storage, 20 GB database, 3-day log retention, the stack can be deleted in one step. See `COST.md`. | Two ALBs and one NAT gateway are the largest fixed costs; they are the price of correct segmentation. |
| Portability | Everything runs as Docker containers; `docker compose up` gives the same three tiers locally. The only AWS-specific code is reading the secret (and it falls back to plain environment variables). | The infrastructure template is AWS-specific; moving to another cloud means rewriting it (the containers need no change). |
